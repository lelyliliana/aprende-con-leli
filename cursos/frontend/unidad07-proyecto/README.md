# Unidad 07. Pruebas, publicación y proyecto propio

[Volver al índice](../README.md)

## Objetivos

Verificar y entregar un proyecto propio con alcance claro.

## Explicación y práctica guiada

Ejecuta npm test y npm run build desde laboratorio. Las pruebas comprueban reglas, almacenamiento, componentes y transferencia entre JavaScript y React. Las comprobaciones de HTTP evalúan el endpoint local. Ninguna sustituye por sí sola la lectura y el teclado en un navegador real.

Generar dist prepara tres páginas y sus assets. Ejecuta npm run preview para revisar ese resultado. Las tareas locales pueden funcionar en alojamiento estático; el endpoint de recursos requiere un servidor disponible. Documenta esa diferencia antes de publicar una copia.

Si necesitas profundizar, consulta [pruebas React](https://github.com/lelyliliana/Curso-React/blob/main/unidad24-pruebas/README.md) y [build](https://github.com/lelyliliana/Curso-React/blob/main/unidad32-build/README.md).

Tu proyecto final puede adaptar el plan a lectura, práctica de idiomas o seguimiento personal de habilidades. Define una persona usuaria, un alcance pequeño y al menos tres criterios de aceptación. Cambiar colores por sí solo no demuestra haber transferido los conceptos.

Entregas sugeridas: maqueta semántica, interacción con JavaScript, datos persistentes, versión React y comprobaciones. Conserva evidencia de fallos y recuperación, además del caso válido. La instalación debe funcionar en una copia nueva sin rutas exclusivas de tu computador.

Autoevalúa con estos criterios: problema y aceptación (15), estructura/diseño accesible (20), interacción/reglas (25), persistencia/errores (15), React y estados remotos (15), pruebas/documentación (10). Los pesos suman 100. Un criterio sin evidencia indica qué debes completar, no una calificación automática.

## Ejercicios

1. Explica qué comprueba una prueba de dominio, una de componente y una petición HTTP real.
2. Construye dist y revisa las tres páginas con preview. Registra las dependencias que no viajarían a un hosting estático.
3. Escribe instalación, ejecución, modelo de datos y límites de tu proyecto; repite el arranque en una copia nueva.

## Reto

Entrega un planificador propio con una mejora de comportamiento y una prueba que detecte su ausencia. Demuestra un fallo controlado y su recuperación.

## Errores frecuentes

Entregar solo capturas; asumir que build significa despliegue; omitir los límites de datos locales; modificar el contrato en una sola implementación.

## Comprobación para avanzar

Puedes instalar, demostrar y explicar tu solución y diferenciar lo probado de lo que todavía falta comprobar.
